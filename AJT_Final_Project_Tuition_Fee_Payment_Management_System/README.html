📖 1. Project Definition

The Tuition Fee Payment Management System is a complete, multi-tiered, role-based institutional fee management and billing web portal. It digitizes the entire lifecycle of student enrollment, course fee assignment, payment collection, receipt generation, and financial reporting for a tuition or coaching institute.

The system provides two secure user portals — one for Admin (institute staff) and one for Students — alongside a standalone Java Swing desktop utility for offline receipt lookup.

Built on the Java EE (Enterprise Edition) technology stack, packaged as a WAR file, and deployed on Apache Tomcat with a MySQL relational backend managed via XAMPP / phpMyAdmin.

🏗️ 2. Architecture & Abstraction

The application follows a classic 3-Tier MVC Architecture with clear separation of concerns enforced at every layer.

🖥️ Presentation Layer

JSP pages with JSTL & EL. Zero Java scriptlets. Pure HTML templates that display data forwarded from Servlets.

⚙️ Business Layer

Java Servlets (Controllers) + Spring-managed Service classes containing all business rules and validations.

🗄️ Data Access Layer

DAO interfaces hide all SQL / HQL. Implementations use JDBC (users, courses) or Hibernate ORM (students, fees, payments).

Key Design Patterns

MVC Pattern — Model (entities + services), View (JSP), Controller (Servlets)
DAO Pattern — Interfaces decouple business logic from database technology
Dependency Injection — Spring IoC injects DAOs into Services via XML config
Singleton Pattern — DBConnection, HibernateUtil, SpringContextHelper

🔌 JDBC — Java Database Connectivity

What: Low-level Java API to execute SQL directly via Connection, PreparedStatement, and ResultSet.

  • DBConnection.java — loads db.properties and opens MySQL connections
  • UserDAOImpl — login authentication via PreparedStatement (SQL injection safe)
  • CourseDAOImpl — full CRUD on courses table
  • FeeReceiptViewer (Swing) — direct MySQL lookup without the web layer

🌐 Java Servlets

What: Server-side Java classes extending HttpServlet that handle HTTP GET / POST. The Controller in MVC.

  • LoginServlet — authenticates users, sets HttpSession, role-based redirect
  • StudentServlet — full student CRUD (list, add, edit, update, delete)
  • CourseServlet — course catalog management
  • FeeAssignmentServlet — assigns fee structures to students
  • PaymentServlet — processes payment, auto-generates TXN & Receipt numbers
  • ReceiptServlet — fetches and forwards receipt data to JSP
  • AdminReportServlet — aggregates course-wise financial data
  • AuthFilter — javax.servlet.Filter for role-based URL protection

📄 JSP + JSTL + Expression Language (EL)

What: JSP is the server-side view technology. JSTL provides HTML-like standard tags. EL provides ${variable} syntax to access data without scriptlets.

  • login.jsp, register.jsp, index.jsp — Public pages
  • admin/dashboard.jsp — KPI cards using EL: ${requestScope.totalStudents}
  • admin/students.jsp — Student list with <c:forEach>
  • admin/reports.jsp — Financial report with <fmt:formatNumber>
  • student/receipt.jsp — Printable payment receipt
  • common/header.jsp, footer.jsp, alert.jsp — Reusable fragments

JSTL Tags used: <c:forEach>   <c:if>   <c:choose>   <c:url>   <fmt:formatNumber>   <fmt:formatDate>

🗺️ Hibernate ORM 5

What: Object-Relational Mapping framework. Maps Java entity classes to database tables, eliminating repetitive SQL for transactional entities.

  • Student.java → students table with @ManyToOne to Course & User
  • FeeAssignment.java → fee_assignments table
  • Payment.java → payments table (TXN ref, receipt number, status)
  • HibernateUtil.java — Singleton SessionFactory initialized once at startup
  • HQL queries: FROM FeeAssignment WHERE student.studentId = :id

Annotations used: @Entity   @Table   @Id   @GeneratedValue   @Column   @ManyToOne   @JoinColumn

🌱 Spring Framework — Core IoC / Dependency Injection

What: Spring Core's IoC container creates and manages object lifecycles, automatically injecting dependencies instead of hardcoding new Object().

  • applicationContext.xml — defines all DAO and Service beans with setter injection
  • SpringContextHelper.java — loads ClassPathXmlApplicationContext, supplies beans to Servlets
  • StudentService ← injected StudentDAO (Hibernate)
  • PaymentService ← injected PaymentDAO (Hibernate)
  • FeeService ← injected FeeDAO (Hibernate)
  • CourseService ← injected CourseDAO (JDBC)
  • UserService ← injected UserDAO (JDBC)

⚠️ Note: This project uses Spring Core only (IoC/DI via XML). Spring MVC is NOT used — plain Java Servlets handle all HTTP routing.

🖥️ Java Swing — Desktop Utility

What: Java's built-in GUI toolkit for standalone desktop applications.

  • FeeReceiptViewer.java — standalone admin desktop tool
  • Connects directly to MySQL via JDBC (no Tomcat / browser required)
  • Displays results in a JTable
  • Search by Receipt Number, Student Roll Number, or Student Name
  • Opens a formatted printable receipt dialog
  • Designed for institute receptionists for fast offline access

🚀 7. Setup & Installation Guide

  1. Start XAMPP — Open XAMPP Control Panel, start Apache and MySQL. Go to http://localhost/phpmyadmin/ → Import tab → Select database/tuition_fee_management.sql → Click Go.
  2. Open Project in NetBeans — File → Open Project → Browse to d:\AJT Prj (contains pom.xml). NetBeans auto-detects it as a Maven Web Application.
  3. Configure Apache Tomcat — Services tab → right-click Servers → Add Server → Apache Tomcat/TomEE → point to Tomcat installation directory → Finish.
  4. Check DB Credentials — If MySQL has a password, update src/main/resources/db.properties and hibernate.cfg.xml. (Default: root / no password on port 3306)
  5. Run Web Application — Right-click project → Run (F6). Browser opens at: http://localhost:8080/TuitionFeeManagement/
  6. Run Swing Desktop Utility — Navigate to com.tuitionfee.swing.FeeReceiptViewer.java → right-click → Run File (Shift + F6).
